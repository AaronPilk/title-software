# Ballantyne requirements: implementation and production readiness

Updated September 14, 2026. This records the implementation against the supplied **AI System Developer Requirements — Revised** (26 pages) and **Information Needed Before Production** (10 pages). The original PDFs remain outside the repository. Their proposed operating rules still require business confirmation where the documents differ.

**Current release status:** OCR, multiple-company Missive routing and workspace credential settings are deployed to the private pilot, including the September 14 follow-up fixes below. Automated regression verification is complete for this patch. Owner connection setup and a signed-in staff acceptance walkthrough remain pending.

**SoftPro Select remains the intended production authority.** The application now has a working preparation and review layer around that model. It has no live SoftPro reader, writer, order-creation API, database integration or screen automation. A saved mapping or human-recorded outcome does not establish a vendor connection.

## What is implemented

| One Select environment with separate JV companies; configurable company context | **Connections → Setup** records versioned company identifiers/names, underwriter, inbox aliases, template, archive rule, existing SoftPro 360 channel and named approvers. | Repeated revisions with source and old/new values | **Connections → Review queue** captures the manually observed SoftPro value, requested value, source document/version/page/quotation, observation evidence and reason. Pausing blocks new proposals, approvals and recording applied outcomes; history remains readable. | Missive messages, attachments and event intake | Existing reviewed message import preserves conversation/message identity and original source history. New server code saves selected original attachment bytes with immutable attribution and SHA-256 metadata. A signed webhook receiver durably queues source metadata for review. Receiving or reading an email never completes a title file. | Version 2 routing supports one company or a portfolio of approximately 25 JVs, with up to 500 routes. Actual inbox/company approvals and a live message-import acceptance case remain to be completed. |

Original files remain unchanged. | OCR is one page per run: 25 MB, 120 PDF pages, 12 MP source images, 4 MP rendered pages and a 90-second limit. Worker, WASM and English model assets come from the app origin, with no OCR document upload or third-party CDN fetch. Handwriting, faint scans, complex tables and critical wording need manual review. OCR is not automatic structured-field interpretation or a SoftPro write. |

| Shared work, permissions, audit and recovery | Existing Supabase-backed commands, company permissions, restricted-document access, conflict checks, private files and recovery points also cover the new records. Company integration history is withheld together when restricted evidence would otherwise expose an incomplete history. | Business retention, independent disaster recovery, operational support ownership and production acceptance remain to be agreed. ## What Ballantyne needs to provide next

1. **Confirm which real company each connection belongs to.** This is the meaning of “company mappings”: the application company/JV, its company profile inside Select, the inboxes it uses, its underwriter/templates and the people allowed to work there. Start with the existing legal-company list. A shared inbox can belong to several JVs and requires a destination choice; a single-company business needs one company. We can build the routing, but cannot infer the correct legal entity or vendor identifier from a display name. Record verified values in Connections and leave unknown identifiers missing.
2. **Contact SoftPro now for supported integration access.** SoftPro does offer ProInterface/API/SDK integration; the account's license, applicable contract, hosting arrangement and current interface documentation still need confirmation. Ask for the technical representative, approved authentication/service permissions, a test environment and supported field/action identifiers. The application does not need to be finished before this conversation, because those answers determine the connector design. Continue using existing AgentNet, agentTRAX and WFG channels through SoftPro 360. No new separate underwriter connector is assumed.
3. **Approve the business rules.** Name medium/high-risk and final-policy approvers; define readiness, downstream regeneration, late-change, ambiguous-match, cancellation and escalation rules. Decide permitted Missive communications, retention, support, account ownership and recovery responsibilities. Automatic-write permissions remain disabled.
4. **Provide representative acceptance cases.** Use approved anonymized examples spanning new orders, repeated revisions, same-name borrowers, multiple loans, unrelated transactions in one thread, conflicting companies, missing/scanned documents, recording completion and late policy changes. Compare results with staff's actual SoftPro work and capture baseline time/error measurements.
5. **Finish the Missive connection and approved routing.** The complete token now passes discovery. The owner or organization-wide administrator can now use **Settings → Missive account connection** to verify and save the complete token in encrypted workspace storage. Review each company/inbox route, including shared inboxes. Event intake still needs server-side workspace/rule/signing configuration; attachment downloads need the exact approved HTTPS origins. Follow the [Missive setup guide](missive-connection.md). Do not place tokens in source files or browser build variables.
6. **Accept the deployed pilot.** Sign in through Cloudflare and the app, assign the intended company permissions, verify real access and attachment origins, then demonstrate one complete representative case with staff. Start with Observe/Propose. Record business acceptance before introducing any future vendor write capability.

OneDrive upload automation, production monitoring/alerts, automated-processing accuracy and time-saved reporting, vendor-side retries/reconciliation and actual SoftPro integration acceptance remain work to complete after the corresponding business rules and supported access are available.
